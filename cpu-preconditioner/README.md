# Tiny CPU neural-preconditioner experiment

This tests the inverse-solver idea on the **2D fluid interior**, separately from
the production DNO network. No production code or GPU jobs are involved.

For each Tanaka surface, linear triangular finite elements discretize Laplace's
equation on a periodic, surface-following mesh. Surface potential is prescribed;
the flat bottom has zero normal derivative. With the surface nodes eliminated:

```text
A = interior/interior block of the Laplace stiffness matrix
b = -interior/surface block × surface potential
solve A × interior potential = b
surface reaction / horizontal grid spacing = approximate DNO output
```

The network predicts a positive scaling field `D` from geometry, once per
surface. Each preconditioner application is then `D * flat_inverse(D * r)`:
no NN inference inside GMRES. The flat inverse uses a Fourier transform in x
and 33 small vertical inverse matrices, precomputed at mean fluid height.
The network starts at `D=1` and retains that exact limit for flat surfaces.
Its action is linear in the residual, symmetric and positive definite.
Comparisons retain **right-preconditioned flexible GMRES** so the solver is
unchanged from the earlier nonlinear U-Net experiments below. PyAMG supplies
the solver; the final true residual is checked explicitly. See the
[PyAMG documentation](https://pyamg.readthedocs.io/en/latest/generated/pyamg.krylov.html#pyamg.krylov.fgmres).

## Run

From the repository root, using its existing CPU-capable PyTorch environment:

```sh
CUDA_VISIBLE_DEVICES='' OPENBLAS_NUM_THREADS=1 UV_CACHE_DIR=/tmp/codex-uv-cache \
  uv run --no-sync --with pyamg==5.3.0 cpu-preconditioner/run.py \
  --epochs 100 --learning-rate 1e-3 --output outputs/cpu_preconditioner_trial

CUDA_VISIBLE_DEVICES='' OPENBLAS_NUM_THREADS=1 uv run --no-sync --with pyamg==5.3.0 \
  python -m unittest discover -s cpu-preconditioner/tests -v
```

Use a fresh output directory. CPU execution is also enforced inside the script.
The source is `outputs/paper_dataset/arrays`; the nine fixed rows are in `ROWS`.
Six are actual training ICs, three actual test ICs, all at time zero and with
distinct simulation IDs. Depths range from 0.206 to 0.347. Fourier resampling
reduces 1,024 horizontal samples to 64; there are 16 vertical cells and 1,024
interior unknowns, including the bottom nodes.

The 130-parameter pointwise network trains from scratch using two CPU threads
and evaluates using one (less overhead for this tiny network). The user
approved **100 epochs at initial learning rate `1e-3`** for this CPU experiment;
cosine decay ends at `1e-4`. This is an exception to the repo's one-epoch rule,
not a change to production training.

The six training geometries supply 6,144 fixed pairs `(r, A^-1 r)`. Half are
ordinary forcing: white interior noise, smooth manufactured corrections using
all 16 vertical modes, and smooth/broad surface-boundary forcing. Half are the
directions that flat-preconditioned FGMRES passes to its inverse. Source RHSs
are shuffled before collecting directions. These are flat-solver directions,
not directions generated by the evolving neural model.

Sparse LU supplies exact same-grid labels. Each pair is scaled to unit target
RMS. The current loss is relative squared **equation residual** plus `0.01`
times relative squared potential error. Independent draws (128 per training
geometry) provide validation; 48 fixed probes spanning both ordinary and
Krylov inputs select checkpoints by total FGMRES iterations, with validation
loss breaking ties. Selection runs at epochs 0, 1, every 10 epochs, and the
final epoch. A failed true-residual check disqualifies the candidate against
the converged flat baseline. This is RHS validation, not unseen-geometry
validation. The three test geometries and their actual Tanaka potentials never
enter training or selection. Fresh mixed probes also test those geometries.

`results.json` separates **standalone** inverse predictions from solutions
**after FGMRES**. The analytic flat inverse is always evaluated on its own:
the learned correction must improve on that baseline to deserve credit. DNO
error is measured separately because surface differentiation can amplify small
potential errors. Solver timings include every flat inverse and NN application;
matrix/factor setup is reported separately. Training time includes validation
and checkpoint selection.

## Original one-epoch result

The original Jacobi-plus-U-Net pilot used one epoch at `2e-5`, manufactured
corrections with only eight vertical modes, and no boundary-forcing examples.
Completed September 29, 2026; training took **5.12 seconds**. Raw weights,
timings, and short-rollout arrays are in `outputs/cpu_preconditioner_20260929/`.
All methods reached relative equation residual below `1e-9` on all three test
cases. Solve times below are medians of three warmed repeats, including NN
conversion/inference and Krylov work but excluding matrix/geometry setup.

| Method | Iterations across three cases | Solve time |
|---|---|---|
| No preconditioner | 143 / 170 / 173 | 10.0–12.2 ms |
| Jacobi | 135 / 173 / 183 | 9.6–13.0 ms |
| Jacobi + learned correction | 137 / 172 / 183 | 165–225 ms |
| ILU | 6 / 6 / 6 | 0.58–0.61 ms |
| Direct sparse LU | — | 0.048–0.056 ms after factorization |

ILU and direct LU setup each cost approximately 2.0–2.2 ms per geometry.
The learned preconditioner **did not improve convergence and was much slower**.
Its standalone potential error was **97.5%** on the three held-out ICs, almost
identical to Jacobi. The accurate corrected solve below was not evidence that
the network had learned an accurate inverse.

The NN-assisted solve's DNO output agrees with the same-grid direct result to
`3.76e-7` relative or better. Separately, refining from 64×16 to 256×64 changes
the three DNO outputs by 0.305–0.685%; iterative accuracy is not continuum
accuracy. Flat-mode analytic checks and real-IC refinements show approximately
second-order convergence.

A four-step RK4 water-wave smoke test (`dt=0.001`, horizon `0.004`) recomputes
the domain and preconditioner geometry at every stage. NN-assisted and direct
paths use the same coarse FEM discretization. Final eta/xi differences are
`3.62e-10` / `2.19e-12` relative; wall times are 2.67 / 0.043 seconds. This is
only a coupling check—not the production GL2/filter protocol or a long-rollout
stability/accuracy result.

## Trained flat-inverse correction

September 30: this earlier recipe used ordinary RHSs only, potential MSE plus
`0.01` times equation-residual MSE, and validation-loss checkpoint selection.
The approved 100-epoch run took **8 minutes 35 seconds**, including
validation and checkpoint selection. Epoch 100 had the best validation loss:
`4.35e-5`, versus `2.82e-3` for the untrained flat baseline. Results and weights:
`outputs/cpu_preconditioner_flat_20260930/`.

These are predictions **before GMRES**, compared with the same-grid direct solve:

| Held-out simulation | Flat potential error | Flat + NN potential error | Flat + NN DNO error |
|---|---:|---:|---:|
| 16477 | 1.241% | 0.927% | 124.8% |
| 16494 | 3.886% | 0.458% | 57.0% |
| 16602 | 4.633% | 0.377% | 27.9% |

On 128 fresh mixed RHSs per unseen geometry, learned potential error has medians
0.80–0.84% and 95th percentiles 1.04–1.16%. Thus the correction actually learned
an inverse approximation; it is not just exploiting the physical test RHSs.
However, potential accuracy still does **not** give an accurate standalone DNO.

FGMRES iterations fall from **6 / 8 / 8** with the flat inverse to **5 / 7 / 7**
with its learned correction. All solves converge, but the NN adds overhead:
**6.53–9.11 ms versus 0.60–0.76 ms** for flat-only FGMRES. ILU takes 0.57–0.59 ms.
The analytic flat inverse accounts for most of the improvement over the original
Jacobi pilot. This is progress in inverse prediction, **not a CPU acceleration
or a standalone DNO replacement**. No production model or GPU job was changed.

An independent four-step RK4 check **without GMRES**, using the first test IC,
gives final eta errors 0.197% (flat) and 0.120% (flat + NN) against the same-grid
direct rollout. All states stay finite, but the horizon is only `0.004`; this
does not establish useful long-time accuracy. The original GMRES-corrected
smoke agrees to `2.33e-12` in eta because it solves the equations accurately.
Both diagnostics are saved in the result directory.

## Training on GMRES directions

October 1: the previous network's training-geometry potential errors were small,
but equation errors on directions requested by FGMRES reached 5–11%. The training
recipe above targeted that gap while retaining the 5,609-parameter U-Net.
The user approved another fresh 100-epoch CPU run at `1e-3`; it took **8 minutes
38 seconds**. Epoch 100 was selected by validation iterations: mean **5.71**,
versus **7.33** for the previous NN and **7.88** for the flat inverse on the same
48 probes. Results: `outputs/cpu_preconditioner_krylov_20261001/`.

Additional test ICs were selected from metadata before loading the final model:
three each from main one/two/three-crest and steep one-crest groups per cohort,
excluding all original nine simulations. One cohort matches the training depth
range (0.206–0.347); the other spans broader depths, including 0.018. Matching
depth alone does not establish full distributional coverage.

| FGMRES iterations | Flat inverse | Previous NN | New NN |
|---|---:|---:|---:|
| Original three test ICs | 6 / 8 / 8 | 5 / 7 / 7 | 4 / 6 / 6 |
| 12 additional ICs, training-depth range (mean) | 7.08 | 6.17 | 5.33 |
| 12 additional ICs, broader depths (mean) | 6.58 | 7.08 | 6.00 |

On the additional 24 cases, the new NN beats the old NN 18 times and ties six,
with no regressions. Against flat-only it wins 18, ties four, and loses two
(depths 0.0657 and 0.0184). All 96 method/case combinations in the expanded
audit reach true FP64 residual below `1e-9`; NN inference remains FP32.

Iteration reduction still does **not** overcome NN cost. In the paired expanded
audit, median solve times are 8.82/11.38 ms for the new NN versus 0.68/0.66 ms
for flat-only (training-depth/broad cohorts). Median paired new/old timing
ratios are 0.987/0.887; timing noise makes precise speedup claims inappropriate.
A nonlearned second flat correction achieves mean 4.00/4.08 outer iterations
and about 0.6 ms, but spends **two flat inverses and one extra A application per
preconditioner call**. The artifact records these operations explicitly.

The three original standalone potential errors are 0.334/0.932/1.455%, and DNO
errors 19.7/61.2/38.6%; optimizing solver iterations need not improve every
standalone field error. The four-step corrected rollout still agrees with
direct FEM to `7.99e-12` in eta, but remains only a coupling check. Keep this
isolated as a better learned preconditioner, not a production acceleration.

## Cached geometry coefficients

October 2: replaced per-iteration U-Net inference with the geometry-only scaling
described above. Same training pairs, loss and validation selection; fresh
weights, approved 100 epochs at `1e-3`. Training took **91 seconds**, selecting
epoch 80. Mean validation iterations barely improve: **7.83 versus 7.88** for
flat-only, and worse than the previous U-Net's **5.71**. A diagonal scaling
cannot represent the previous network's general spatial correction.

The fixed 27 held-out ICs were evaluated with all methods sharing the optimized
flat inverse and one-thread inference. Seven warmed repeats per case, randomized method order, include
flat-block setup, geometry features, coefficient prediction, solve and true
residual verification. Common FEM assembly is separate (about 0.55 ms).

| Method | Original three iterations | Additional 12, training-depth mean | Additional 12, broad-depth mean | Median setup + solve across the three cohorts |
|---|---:|---:|---:|---:|
| Flat inverse | 6 / 8 / 8 | 7.08 | 6.58 | 0.87–0.98 ms |
| Analytic height scaling | 4 / 7 / 8 | 6.42 | 5.67 | 0.82–0.93 ms |
| Two flat corrections | 3 / 4 / 5 | 4.00 | 4.08 | 0.82–0.84 ms |
| Previous U-Net | 4 / 6 / 6 | 5.33 | 6.00 | 4.67–5.09 ms |
| Cached NN | 4 / 7 / 8 | 6.25 | 6.08 | 1.20–1.25 ms |

The analytic control uses `D=sqrt((h+eta)/(h+mean(eta)))`, without training.
Against it, the cached NN improves iterations on four cases, ties 18, and
regresses on five. Caching is **about four times faster than the U-Net**, but
is not a runtime or iteration win over the inexpensive nonlearned controls.
Each cached application costs about 24 microseconds. A separate setup benchmark
found one-thread inference 1.54 times faster than two threads, with bitwise
identical coefficients; disabling MKLDNN gave no additional benefit.

All 945 timed solves converge, with maximum true relative residual `9.83e-10`.
On the original three ICs, standalone potential errors are 0.113/0.316/0.504%,
but standalone DNO errors remain 3.54/18.39/24.98%. The four-step corrected
smoke agrees with direct FEM to `2.05e-11` in eta and `1.99e-13` in xi; again,
this is not a long-rollout result. Keep the cached formulation as an isolated
cost experiment, not a production solver improvement. Results, weights and the
paired audit are in `outputs/cpu_preconditioner_cached_20261002/`. The table uses
`paired_eval_1thread.json`; the earlier two-thread audit is also retained.

Read `laplace.py` for the discrete operator and `run.py` for the network,
training loop, solver comparison, and short coupled test.
